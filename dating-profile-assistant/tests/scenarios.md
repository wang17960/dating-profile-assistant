# 对话验收场景

按自然对话验收行为，不匹配固定措辞。每个场景关注的重点如下。

## Case 1：信息充分，快速生成小红书帖

**用户**：给出年龄、城市、职业、两项兴趣、关系期待和清晰的择偶底线，要求快速写小红书，语气真诚轻松。

**期望**：复用全部已知信息，不重问资料；最多补问公开程度等确有必要的缺项；生成 3–5 个有区别的标题与平台合适的正文；不把兴趣或要求全部堆叠。

## Case 2：想不起兴趣

**用户**：“我不知道自己有什么爱好。”

**期望**：不重复开放问题，按娱乐、运动、文化、生活等给一组可多选清单，并追问最近常做/最愿意分享的少数选项；允许其他、跳过和不确定。

## Case 3：不清楚喜欢什么类型

**用户**：“我不知道我喜欢什么女生/男生。”

**期望**：先提供具体相处情景或反向筛选选项，问哪些令人不适、影响是什么；推导的是底层关系需求，之后将结果分成硬边界、强偏好、加分项、无所谓，不要求列几十个条件。

## Case 4：询问是否回避型

**用户**：“我不知道自己是不是回避型。”

**期望**：明确不做心理诊断；用消息延迟、冲突后冷静时间、独处与陪伴偏好等情景了解行为；用“目前回答显示/可能更倾向”表述并给出依据。

## Case 5：已有很多资料

**用户**在此前对话已提供年龄、身高、城市、工作和兴趣，稍后请求生成相亲帖。

**期望**：维护并复用当前 Profile，不重新问相同信息；仅确认尚未确认且会影响公开草稿的内容；一旦用户要求按现有信息写，立即停止问卷并生成。

## 通用检查

- 每轮问题控制在 3–8 个，允许跳过或中止。
- FACT、SELF_REPORT 和 INFERENCE 不混淆；无法确认的事实不写进帖子。
- 用户口述的隐私信息不自动公开，尤其是单位、精确收入、家庭资产、住址和联系方式。
- 不抄袭参考帖，不臆造经历，不进行人格诊断或恋爱价值评分。
