# 择偶偏好分析

帮助用户从模糊的“想找合适的人”走到具体、可沟通的匹配条件。择偶条件不等于对他人的价值评判。

## 先找需求，再列条件

1. 收集用户明确偏好。若表述抽象（如“情绪稳定”“有责任心”），追问可观察的相处行为：遇到压力怎么沟通、承诺是否兑现、冲突后如何修复。
2. 如果用户不知道，启动反向筛选：从 [questionnaire.md](questionnaire.md) 第 11 节选择令人不适的情景，再问它会造成什么影响。由具体后果反推底层需求，例如“长期失联”可能指向稳定联系，而不是要求秒回。
3. 依据婚恋目标澄清不可替代条件：婚育、城市/异地、生活习惯、安全与尊重边界等。
4. 将条件分类，不能把所有愿望都列成硬性要求：
   - **硬边界**：触碰即不适合继续，例如不一致的婚育目标、暴力威胁、重大诚信问题。
   - **强偏好**：高度重视但愿意了解具体情况。
   - **加分项**：有则更合拍，没有也可建立关系。
   - **无所谓/未定**：目前不是筛选依据，或本人还在探索。
5. 检查边界与偏好是否混淆、条件是否相互矛盾、是否来自外界压力而非本人需要。只提出问题，不替用户取消边界。

## 反向筛选法

把“我不要什么”转换为“我需要什么互动条件”，遵循：

- 先区分行为与标签。避免“不要妈宝”“不要渣男”这类含糊且贬损的概括，询问具体行为和家庭边界。
- 每项说明影响及容忍度：完全不能接受 / 介意但可以讨论 / 可磨合 / 无所谓 / 喜欢。
- 不把一项偏好直接推断为普遍人格需求；用其他情景确认。
- 形成不超过 3–5 条优先筛选点，避免把清单变成不可能满足的规格表。

## 城市、外形与客观条件

年龄、身高、学历、收入、房车、职业等条件可以如实记录，但不推导人的价值或恋爱等级。需要时探询实际理由（生活半径、共同规划、吸引力、风险承受能力），提醒用户区分“公开帖需要写什么”和“私下筛选看什么”。不得擅自删掉用户的标准，也不替其承诺找到特定匹配。

## 匹配分析输出

描述维度与适配机制，不宣称某类人必然成功：

- 生活节奏和社交能量
- 联系、沟通与冲突修复
- 独立空间和陪伴需求
- 婚育与家庭边界
- 金钱观、城市和长期规划
- 兴趣共享与差异容纳

每个判断指出来自哪些事实或自述。将“也许更容易相处”与“必须满足”分开；注明仍未知的信息。
